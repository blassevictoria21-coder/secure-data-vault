# AGENTS.md — Secure Data Vault

Educational "secure data vault": salted SHA-256 password hashing + AES-256-GCM encryption of records at rest, with a dashboard, a raw-DB evidence viewer, a printable security manual and a 10-slide defense deck. The brief that drives every decision: Users + Records tables, SHA-256 + salt, AES before write, authorised decrypt-and-display.

## Architecture

- `netlify/server/index.ts` — **the only backend**: a Hono app exported as default with `config.path = "/api/*"`. Netlify Server, not Netlify Functions. Do not add a full-stack framework; its catch-all function would shadow the server.
- `netlify/server/lib/crypto.ts` — all cryptography (hashing, AES-GCM, HKDF key derivation, key loading). Keep crypto here only.
- `netlify/server/lib/session.ts` — stateless HMAC-signed session cookie (`vault_session`, 30 min).
- `db/schema.ts` — Drizzle schema (source of truth); `db/index.ts` — client (`drizzle-orm/netlify-db`).
- `netlify/database/migrations/` — generated by `npx drizzle-kit generate --name <name>`. Never edit applied migrations; never apply them manually.
- `public/` — static site (publish dir). No build step for the frontend: plain HTML + ES modules in `public/js/`, CSS in `public/css/`.
- `scripts/export-source.mjs` — build command; copies source files into `public/source/` (gitignored) for the manual's Appendix A. **If you add or rename a source file, update its file list.**

## Non-obvious decisions

- Password hashing is **single-pass salted SHA-256 on purpose**, because the brief requires it. The manual documents the stronger alternatives (Argon2id/PBKDF2) as future work. Don't silently swap the algorithm; the `hash_algorithm` column is there for an upgrade-on-login migration.
- The record payload `{title, subject, body}` is JSON-serialised and encrypted as one blob. `category` stays plaintext because it is not sensitive and is used for filtering.
- AAD = `secure-data-vault:record:owner=<ownerId>`, so changing a row's `owner_id` breaks decryption. This is intentional (anti-swap).
- Master key: `VAULT_MASTER_KEY` env var if set, otherwise a key auto-generated into Netlify Blobs store `vault-keys` (`onlyIfNew`). Changing or deleting it makes existing records undecryptable.
- `ensureKeys()` runs as `/api/*` middleware; the sync crypto functions throw if called before it.
- CSP is strict (`script-src 'self'`, no inline styles/scripts). Build DOM with the `h()` helper in `public/js/api.js` (uses `textContent`). Never use `innerHTML` with data.
- `/api/evidence` deliberately returns raw ciphertext and the caller's own hash and salt, for the evidence screenshots.

## Conventions

- TypeScript server code with ESM `.js` import suffixes.
- snake_case DB column names, camelCase in TS.
- Design tokens are in `public/css/vault.css` (charcoal steel, bone, brass, and rust for ciphertext). Instrument Serif for display text, IBM Plex Sans for body, JetBrains Mono for data.
